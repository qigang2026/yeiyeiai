## 0. 一句话定位

让"想用 AI 工具做 OZON/WB 跨境电商"的卖家，在 **3 分钟内**完成账号创建 + 企业实名 + 7 天免费体验开通，立即进入 `business-dashboard`，完成「首次产品上传 → 第一次 AI 跑数据」的全链路。

## 1. 业务背景与痛点

### 1.1 现状描述

- 注册入口散落在官网首页 Banner、运营朋友圈、社群投放链接，缺乏统一的 funnel 跟踪。
- 老版本注册页需要 5 步、填 12 个字段，平均完成率 38%。
- 7 天免费体验申请是**单独流程**，要走客服加微信，链路长。

### 1.2 痛点本质

1. **注册路径太长**：传统 B 端 SaaS 注册流程 > 5 分钟，跨境卖家耐心低。
2. **无即时反馈**：付费/试用都要走线下，用户感知不到"我已经开通了"。
3. **缺少渠道归因**：不知道用户是从哪个推广渠道来的，无法给渠道商分佣。
4. **手机号未强校验**：导致后期短信验证码命中率低，影响账号找回链路。

### 1.3 价值主张 (Why now)

- **对用户**：3 分钟完成所有注册，**立即看到产品效果**（"你开通的 1 个店铺授权已可用"）。
- **对业务**：把注册转化率从 38% 提升到 55%，单注册成本下降 30%。
- **对渠道**：通过 `?utm_source` + `partner_code` 参数，让合伙人 Dashboard 能准确归因（联动 `partner-dashboard.html`）。

## 4. 核心功能模块设计

### 4.1 模块 A：注册表单

#### 4.1.1 字段定义

| 字段名 | 类型 | 必填 | 校验规则 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `company_name` | string | ✓ | 长度 2-50；中英文数字 · ( ) 空格 - | — | 公司名称，开通合同抬头 |
| `contact_name` | string | ✓ | 长度 2-20；中文 / 英文 | — | 联系人姓名 |
| `phone` | string | ✓ | `^1[3-9]\d{9}$` | — | 中国大陆手机号 |
| `username` | string | ✓ | 长度 4-20；`^[a-zA-Z][a-zA-Z0-9_]*$` | — | 登录账号，开头必须是字母 |
| `password` | string | ✓ | 长度 8-32；必须含字母+数字 | — | 登录密码 |
| `password_confirm` | string | ✓ | 必须与 `password` 一致 | — | 二次确认 |
| `partner_code` | string | ✗ | 长度 4-32；字母数字下划线 | 从 URL `?utm_source=` 读取 | 渠道来源标识 |

#### 4.1.2 业务规则

- **规则 1**：注册成功后，系统自动创建「Tenant Admin」角色，并把 `company_name` 作为租户显示名。
- **规则 2**：手机号**不能重复**，已注册手机号在失焦时立即提示「该手机号已注册」。
- **规则 3**：用户名前端不查重，但提交时若后端返回 409，给出「账号名已存在」提示。
- **规则 4**：密码强度分三档：
  - **弱** (< 8 位)：仅满足长度
  - **中** (≥ 8 位 + 字母数字)：基本安全
  - **强** (≥ 10 位 + 大小写字母 + 数字 + 特殊符号)：推荐
- **规则 5**：`partner_code` 不在前端展示字段，但注册请求体里要带上。

#### 4.1.3 状态机

```
[未提交] -- 点击注册/试用 --> [提交中]
[提交中] -- 成功 --> [注册成功 / 试用弹窗]
[提交中] -- 失败 --> [未提交 + 错误提示]
[注册成功] -- 确认开通试用 --> [进入业务后台]
```

### 4.2 模块 B：7 天免费体验弹窗

#### 4.2.1 弹窗字段

| 元素 | 内容 | 备注 |
| --- | --- | --- |
| 标题 | 开通 7 天免费体验 | |
| 描述段 1 | 确认开启 7 天免费体验吗？系统将立刻创建租户、开通 1 个店铺授权，您可以直接进入系统使用全部功能。 | |
| 描述段 2 | 体验期结束后如未续费，账号将无法继续访问。到期前请在「全局设置 → 租户到期」处查看剩余天数。 | 引导用户后续动作 |
| 按钮 | [取消] / [确认开通] | 取消走「返回表单」分支 |

#### 4.2.2 业务规则

- **规则 1**：手机号不合法时不能点开体验弹窗，强制走正常注册流程。
- **规则 2**：体验弹窗只是**前端引导**，真正的租户创建发生在「确认开通」之后。
- **规则 3**：体验期默认开通 **1 个店铺授权**，到期不续费则冻结租户。

## 5. 数据契约

### 5.1 后端 API

| 接口 | 方法 | 路径 | 请求体 | 响应体 | 错误码 |
| --- | --- | --- | --- | --- | --- |
| 注册账号 | POST | `/api/auth/register` | `{company_name, contact_name, phone, username, password, partner_code?}` | `{user_id, tenant_id, token}` | 40001-40099 |
| 申请试用 | POST | `/api/tenant/trial` | `{user_id, company_name, contact_name, phone}` | `{tenant_id, expire_at}` | 40301 |
| 查重手机号 | GET | `/api/auth/phone-exists?phone=xxx` | — | `{exists: boolean}` | — |
| 查重用户名 | GET | `/api/auth/username-exists?username=xxx` | — | `{exists: boolean}` | — |

### 5.2 关键字段定义（TypeScript）

```typescript
interface RegisterRequest {
  company_name: string;
  contact_name: string;
  phone: string;            // 11位中国手机号
  username: string;         // [a-zA-Z][a-zA-Z0-9_]{3,19}
  password: string;         // 8-32 位，含字母+数字
  partner_code?: string;    // URL ?utm_source= 携带
}

interface RegisterResponse {
  user_id: string;
  tenant_id: string;
  token: string;
}

interface TrialRequest {
  user_id: string;
  company_name: string;
  contact_name: string;
  phone: string;
}

interface TrialResponse {
  tenant_id: string;
  expire_at: string;  // ISO 8601，例如 "2026-09-10T00:00:00+08:00"
}
```

### 5.3 错误码

| 码 | 含义 | 用户提示文案 |
| --- | --- | --- |
| 40001 | 参数缺失 | 请检查并完善表单内容 |
| 40002 | 手机号格式错误 | 请输入正确的手机号 |
| 40003 | 用户名格式错误 | 用户名 4-20 位，字母开头，仅含字母数字下划线 |
| 40004 | 密码强度不足 | 密码需 8-32 位，含字母和数字 |
| 40005 | 手机号已注册 | 该手机号已注册，请直接登录 |
| 40006 | 用户名已存在 | 用户名已存在，请更换 |
| 40301 | 试用申请拒绝 | 当前账号不符合试用条件 |

## 6. 交互细节与校验规则

### 6.1 表单校验

| 字段 | 触发时机 | 规则 | 错误提示文案 |
| --- | --- | --- | --- |
| 公司名称 | 失焦 | 非空，长度 2-50 | 请输入公司名称（2-50 字符） |
| 联系人 | 失焦 | 非空，长度 2-20 | 请输入联系人姓名（2-20 字符） |
| 手机号 | 失焦 + 提交 | `^1[3-9]\d{9}$` | 请输入正确的手机号 |
| 用户名 | 失焦 + 提交 | 字母开头，4-20 位 | 用户名 4-20 位，字母开头 |
| 密码 | 输入时实时 + 失焦 + 提交 | ≥8 位 + 含字母数字 | 密码需 8-32 位，含字母和数字 |
| 确认密码 | 输入时实时 + 失焦 + 提交 | = 密码 | 两次输入的密码不一致 |

### 6.2 异常路径

| 异常场景 | 触发条件 | 用户感知 | 系统处理 |
| --- | --- | --- | --- |
| 网络断开 | `navigator.onLine === false` | 顶部黄色 banner「网络已断开」 | 表单暂存到 localStorage，恢复后提示 |
| 接口 500 | 后端错误 | 顶部红色 toast「服务异常，请稍后重试」 | 自动重试 1 次后停止 |
| 手机号已注册 | 409 + 40005 | 手机号字段红字「该手机号已注册」 | 引导到「返回登录」链接 |
| 用户名已存在 | 409 + 40006 | 用户名字段红字「用户名已存在」 | 焦点定位到 username 输入框 |
| 试用申请被拒 | 403 + 40301 | 顶部 toast + 弹窗不关闭 | 引导用户联系客服 |

### 6.3 可访问性 (a11y)

- 键盘 Tab 顺序：公司名称 → 联系人 → 手机号 → 用户名 → 密码 → 确认密码 → 切换显示密码 → [注册] → [7天体验]
- 错误提示用 `aria-live="polite"` 包裹，失焦校验立即读出
- 密码强度条用 `role="meter"` + `aria-valuenow`
- 所有按钮 `:focus-visible` 显示 2px 紫色描边

## 7. 异常与边界场景

### 7.1 数据边界

- **空表单提交**：拦截所有空字段，焦点跳到第一个空字段
- **超长输入**：maxLength 限制（公司 50 / 联系人 20 / 用户名 20 / 密码 32）
- **超长密码粘贴**：粘贴 > 32 字符自动截断，不报错

### 7.2 业务边界

- **跨租户**：同一手机号不能重复注册（避免账号冲突）
- **重复提交**：注册按钮点击后立即 disabled，loading 态显示
- **partner_code 校验失败**：注册请求依然发送，后端记为 `none`，不报错
- **试用申请失败但注册成功**：保留账号但提示「试用申请被拒，请稍后重试」

## 8. 前端实现要点 (HTML → 组件映射)

### 8.1 组件拆分建议

| HTML 区块 | 推荐组件名 | 复用范围 | 备注 |

| 7 天试用弹窗 | `<TrialConfirmModal>` | 本页 | |
| 顶部 toast | `<Toast>` | 全局 | |

### 8.2 状态管理

- **本地状态**：`formData` / `errors` / `submitting` / `showTrialModal`
- **服务端状态**：注册成功后把 `token` + `tenant_id` 写入 `localStorage`，全局可读
- **全局状态**：当前用户从 `AuthContext` 取

### 8.3 关键技术决策

| 决策点 | 推荐方案 | 理由 |
| --- | --- | --- |
| 表单库 | React Hook Form + Zod | 校验规则可复用本 PRD §6.1 |
| 密码强度 | zxcvbn 库 | 行业标准 |
| HTTP 客户端 | axios + 拦截器 | 已有基建 |
| Token 存储 | httpOnly cookie（首选） / localStorage（兜底） | 安全优先 |

### 8.4 与现有代码的对接

- 复用组件：`<AuthLayout>`（login/register 共享布局）
- 复用样式：`@color-primary: #5b5ce2`、`@color-danger: #ff4d4f`
- 国际化：`register.form.company_name` 等 key 走 i18n
- 渠道来源：URL `?utm_source` 解析后写进注册请求体，与 `tenants.html` 的 `partner_code` 字段对齐
